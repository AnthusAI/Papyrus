# MCP authorization hosting

MCP authorization is available only when the private grant service is configured and `PAPYRUS_MCP_OAUTH_CLIENTS` maps public client IDs to exact registered redirect URIs. Redirects must use HTTPS or HTTP on loopback. The configured `PAPYRUS_CONSOLE_ORIGIN` is the issuer and MCP resource origin; clients discover it at `/api/mcp/oauth/resource` and `/.well-known/oauth-authorization-server`. The configured origin must route both paths, `/api/mcp/oauth/*`, `/mcp/authorize`, and `/api/mcp` to the CMS. A separate console distribution with the CMS as its default origin does so. A shared public distribution needs explicit forwarding for `/.well-known/oauth-authorization-server` and `/mcp/authorize`, in addition to its existing `/api/*` forwarding; confirm those behaviors before enabling the service.

Staff use the newsroom sign-in on the configured origin, then return to the open consent page. A reader may sign in and return automatically when the console and public site share an origin. Prospectus uses a host-only sealed session cookie, so reader authorization is unavailable on a separate console origin until a trusted cross-origin handoff exists. Staff and reader identities are selected explicitly and are never substituted for one another.

Register a public native client's ID and exact redirect in `PAPYRUS_MCP_OAUTH_CLIENTS`; the client uses authorization code with S256 PKCE and token authentication method `none`. The authorization response identifies the configured issuer with `iss` and returns the client's state. Discovery does not require the consent sealing secret, but opening consent requires it.

The current browser federation does not obtain or store an upstream refresh grant for MCP. Its grant is capped at the verified browser JWT expiry (the earlier of the staff access and ID tokens, or the reader session expiry). MCP access tokens last at most 15 minutes and may rotate within that existing deadline; the person must authorize again when it expires. The seven-day maximum is an upper bound on a future longer upstream authorization, not a seven-day browser login.
